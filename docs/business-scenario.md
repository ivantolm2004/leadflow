# Воспроизводимый бизнес-сценарий

## Контекст

Небольшая сервисная компания получает обращения с сайта и из Telegram. Менеджеру нужна единая воронка, которая отбрасывает некорректные данные, показывает состояние заявок и сохраняет результат после перезапуска API.

Сценарий не имитирует внешние CRM или мессенджеры: поле `source` показывает канал, из которого адаптер передал бы заявку в единый HTTP-контракт.

## Запуск

Требуется Node.js 20 или новее. Внешние зависимости и запущенный сервер не нужны.

```bash
npm run scenario
```

Скрипт создаёт временное JSON-хранилище, поднимает API на свободном порту и удаляет временные данные после проверки. При несовпадении фактического результата с ожидаемым команда завершается с ненулевым кодом.

## Что проверяется

| Шаг | Вызов | Проверяемый результат |
|---|---|---|
| Готовность | `GET /health` | `200`, сервис готов |
| Ошибка ввода | `POST /api/leads` с невалидным email | `422`, заявка не попала в воронку |
| Заявка с сайта | `POST /api/leads` | `201`, статус `new`, источник `Website` |
| Работа менеджера | два `PATCH /api/leads/:id/status` | переход `new → work → done` |
| Заявка из Telegram | `POST /api/leads` | `201`, источник `Telegram` |
| Персистентность | перезапуск API и `GET /api/leads` | данные прочитаны из того же JSON-файла |

Ожидаемая итоговая сводка:

```json
{
  "total": 2,
  "new": 1,
  "work": 0,
  "done": 1
}
```

## Связь с автоматической проверкой

`npm run verify` сначала запускает unit и HTTP integration tests, затем этот сценарий. Та же команда выполняется в GitHub Actions, поэтому зелёный CI подтверждает не только отдельные функции, но и полный путь заявки через API и хранилище.
